We need to enhance the Asset Management Dashboard with a file mapping review and persistent mapping system.

Problem to Solve

The current parser is not reliably mapping uploaded Budget and T12 files into the dashboard categories. Important categories are sometimes omitted or misclassified.

This creates a major issue because:

individual line items do not always roll up correctly into dashboard totals

expense detail may not equal total operating expenses

income and expense categories may be missing or incorrectly grouped

the dashboard cannot be trusted unless mappings are transparent and reviewable

We need to add an admin mapping workflow so that uploaded files can be reviewed, corrected, and learned from over time.

Enhancement Objective

Build an admin feature that:

Parses uploaded source files and attempts to auto-map source line items to our predefined dashboard categories

Displays all detected mappings after upload

Clearly highlights:

unmapped source rows

low-confidence mappings

duplicate mappings

rows that appear to be omitted from totals

rows where mapped detail does not reconcile to section totals

Allows the admin user to manually update mappings using a dropdown of predefined dashboard categories

Saves those mappings so they persist and can be reused automatically on future uploads from the same report format/property/source pattern

3. Persistent Mapping Logic

Mappings should persist and be automatically reused in future uploads.

Persist mappings using a mapping rules table that stores things like:

source row name

normalized source row name

source file type

property name if applicable

report type

mapped dashboard category

exclude flag

created by

updated by

created date

updated date

confidence / verification status

Reuse logic

When a future file is uploaded:

first check for an exact saved mapping match

then check normalized/alias match

then fall back to fuzzy matching

if no reliable match is found, leave it unmapped and show it in review

Mappings confirmed by admin should become trusted mappings for future imports.

4. Reconciliation / Validation Checks

This is critical.

The system must perform validation checks before finalizing imported data.

Required checks:

Sum of mapped income detail should reconcile to expected income section totals

Sum of mapped expense detail should reconcile to expected total operating expenses

Sum of mapped debt items should reconcile to total debt & fees

Sum of below-the-line items should reconcile to total below-the-line expenses

If source report contains subtotal rows, compare mapped detail to source subtotal

Flag variances above a configurable threshold

Validation warnings should include:

missing categories

unmapped rows with dollar amounts

duplicate mapped rows

large uncategorized totals

detail total does not match source subtotal

dashboard section total does not match imported source total

The admin should see these warnings clearly before approving import.

Suggested purpose:

mapping_aliases: alternate source labels that map to same dashboard category

import_sessions: one record per upload/import

7. Parsing Improvement Requirements

Improve parser reliability so it can better identify:

section headers

subtotal rows

account detail rows

blank spacer rows

month columns

YTD / QTD / current month columns

inconsistent naming conventions

Use normalization rules such as:

8. Approval Workflow

The import should not silently finalize if key rows are unmapped or reconciliation fails materially.

Recommended workflow:

Upload file

Parse file

Show mapping review table

Show validation/reconciliation warnings

Admin corrects mappings

Save mappings

Re-run parser/reconciliation

Approve finalized import only when acceptable

9. Acceptance Criteria

This enhancement is complete when:

uploaded files show all parsed source rows in a review screen

unmapped rows are clearly visible

admin can manually assign dashboard categories from dropdown

saved mappings persist and apply to future uploads

totals reconcile or clearly show exceptions

expense detail can be validated against total operating expenses

omitted categories are no longer hidden silently

admin has confidence in imported data before dashboard generation

Important Product Principle

For this tool, transparency is more important than automation.

A partially automated parser with a strong review and reconciliation workflow is better than a fully automated parser that silently misclassifies or omits rows.

The system should never hide uncertainty. It should surface uncertainty and let the admin correct it.
